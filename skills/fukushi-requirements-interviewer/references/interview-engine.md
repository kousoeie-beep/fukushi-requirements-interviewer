# 対話エンジン

このファイルはヒアリング開始時に読み、回答ごとの次質問判断に使う。

## 回答者像

- 自社・自事業所の業務は理解している。
- AI、システム、開発、情報管理の専門知識はない。
- 長文の説明より、短い選択肢の方が答えやすい。
- 制度の条文、正確な件数、システム仕様は記憶で答えられなくてよい。

## 内部台帳

会話中は次を内部的に更新する。質問項目として一括表示しない。

| 項目 | 記録内容 |
|---|---|
| 対象法人・事業所・サービス | 誰のどの仕事か |
| 解決したい問題 | 困っている人、起きている影響、頻度 |
| 最初に作る範囲 | 含める業務、含めない業務、優先理由 |
| 現在の仕事 | 担当者、開始、参照物、手順、判断、受け渡し、完了 |
| 改善後の仕事 | 誰が何を行い、誰が確認し、何が残るか |
| 通常ではない場合 | 欠席、誤入力、差し戻し、遅延、通信不可、端末紛失 |
| 情報の扱い | 見る人、書く人、確定する人、直す人、履歴、保存 |
| AIを使う箇所 | 入力、生成物、勝手に加えない内容、確認者、外部送信 |
| 現行の道具 | 紙、表計算、業務システム、連絡手段、正本 |
| 規模 | 件数、頻度、繁忙時間、拠点、利用端末 |
| 成功と受入 | 現状、目標、測り方、確認する人、通常・例外の合格条件 |
| 根拠 | 回答者、帳票、規程、画面、契約、制度資料 |
| 未解決 | 仮説、資料待ち、判断待ち、矛盾、次の質問 |

各記録には `確認済み`、`希望`、`仮説`、`資料待ち`、`判断待ち`、`対象外` のいずれかを付ける。

## 次の1問を選ぶ手順

回答ごとに以下を上から行う。

1. 今の回答に、意味が複数ある、前回答と矛盾する、対象範囲が変わる、責任者が変わる、のいずれかがあるか確認する。
2. 該当すれば、その違いを短く示して確認質問を1問だけ出す。
3. 該当しなければ、対象業務の要件スロットから不足を列挙する。
4. 次の優先度で、設計への影響が最も大きい不足を1つ選ぶ。
   - 人の安全、個人情報、外部送信、制度・請求判断
   - 最初に作る範囲と対象外
   - 誰が使い、誰が最終確認するか
   - 現在の開始から完了までと正しい情報の置き場
   - 判断条件、例外、訂正、差し戻し
   - 入力と作られる結果、既存の仕組みとの受け渡し
   - 件数、期限、利用場所、端末、通信状況
   - 測定可能な成功条件と受入条件
5. 資料を見る方が正確なら質問を増やさず、資料待ちへ移す。
6. 回答者が答えやすい選択肢へ変換し、質問を1つだけ返す。

## 要件スロット

対象業務ごとに次が埋まっているか確認する。

- 誰が行うか、何のためか、いつ始まるか
- 何を見て、どの順に進め、どこで判断が変わるか
- 誰へ渡し、誰が確認し、何ができたら完了か
- 間違い、欠席、遅延、差し戻し、通信不可の時にどうするか
- 件数、頻度、期限、繁忙時の量
- 誰が見てよいか、誰が書き直せるか、変更履歴が要るか
- 現在どこに情報があり、どれを正しいものと扱うか
- どの程度改善すれば価値があり、何ができれば受け入れるか
- その判断の根拠、最終確認者

## 質問の深さ

1. 目的：誰のどの困りごとを改善するか。
2. 現状：最近の通常例で、開始から完了まで。
3. 分岐：場合による判断、引き継ぎ、例外、訂正。
4. 境界：見てよい人、外部送信、制度判断、既存システム。
5. 検証：件数、時間、成功条件、通常・例外の合格条件。

最初から深い質問をまとめない。選択肢だけで手順が確定できない場合、1業務につき最大1回だけ最近の実例を尋ねる。答えにくそうなら匿名化した帳票や画面見本の依頼へ切り替える。

## 専門語の言い換え

| 内部語 | 回答者への言い方 |
|---|---|
| MVP / PoC | 最初に試す仕組み |
| API / システム連携 | 今使っている仕組みと情報を受け渡す |
| CSV | 一覧のファイル |
| データ移行 | 今ある情報を新しい仕組みに移す |
| 権限 | 誰が何を見たり、書いたり、直したりできるか |
| 認証 | 本人だけが入れるようにする方法 |
| 監査ログ | いつ、誰が、何をしたかの記録 |
| バックアップ | 間違って消えた時に元へ戻せるようにすること |
| オフライン | インターネットがつながらない時 |
| AIの誤生成 | 入力していない内容を勝手に付け加えること |

## 完成度

| 段階 | 判定 |
|---|---|
| L0 候補 | 困りごと・希望が出た |
| L1 業務理解 | 利用者、目的、開始、通常の流れ、完了が分かった |
| L2 ルール理解 | 判断条件、受け渡し、例外、訂正が分かった |
| L3 開発可能 | 入力、結果、見てよい人、既存業務との関係が分かった |
| L4 確認可能 | 測れる受入条件、確認者、根拠資料がある |
| READY | 重大な矛盾がなく、開発して受入確認できる |

最初に作る必須機能は READY、または「確認責任者・確認資料・確認期限」が付いた確認待ちにする。

## 負担の制限

- 1回1問、選択肢3〜6個、その他、分からない／未定。
- 5問ごとに継続確認し、1回10問程度を目安にする。
- 自由回答は1業務につき最大1回を目安にする。
- 1回答が複数項目を満たしたらすべて記録し、個別に再質問しない。
- 資料依頼は1回1件。必要な理由と匿名化でよい旨を添える。
